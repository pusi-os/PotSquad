# 08 — Инструкция для агентов: коммиты и синхронизация с GitHub

Этот документ — рабочий регламент, по которому ассистент (агент)
правит репозиторий, не мешая активной разработке. Люди могут проигнорировать
эту страницу; агенты — нет.

## Карта репозитория

- `origin` = `https://github.com/pusi-os/PotSquad.git` (организация `pusi-os`).
- Ветки: `main` — основная работа; крупные переработки заводятся в
  отдельную ветку, пулл-реквест — тоже норма.
- CLI: `gh` установлен (`mise install gh`), вход выполнен под учётной
  записью владельца организации.

## Как править и коммитить

1. **Прежде чем менять — посмотри `git status`.** В рабочей копии почти
   всегда идёт активная разработка (сейчас — локализация). Правило:
   **незакоммиченные чужие правки не трогать и не затирать.**
   `git checkout -- <файл>`, `git restore`, `git stash` агенту запрещены,
   пока адекватного разрешения не дал владелец в явном виде.
2. **Коммить только то, что менял сам.** `git add -p` для точечной
   постановки; никогда `git add -A`, если в статусе есть незнакомые файлы.
3. Сообщение коммита — короткое, в стиле истории репозитория
   (`git log --oneline`): сначала имя подсистемы, потом суть, по-английски:
   `Potsy: RU quips for the pet banks`.
4. **Не переписывать историю** (force-push поверх опубликованного) на `main`.
   `--force-with-lease` допустим только в собственную ветку агента и
   только когда точно знаешь, зачем.
5. Пуш: `git push origin main` — обычный, без `--force`. Если пуш
   отклонён, сначала `git fetch` + `git pull --rebase=false` без
   затирания, разобраться руками.

## Синхронизация с GitHub

```sh
git status                      # что лежит в рабочей копии
git add <твои файлы>            # только твои
git commit -m "<в стиле log>"
git push origin main
```

Экстренный случай (пуш отклонён, а локально пусто чужого):

```sh
git fetch origin
git pull --rebase=false          # merge или разбор руками
git push origin main
```

## Что агент не делает

- Не правит `src/*.cpp`, если задача — документация: там живёт человек.
- Не обновляет локализационные файлы (`*_ru*`, строки `ru ? ... : ...`)
  без прямой задачи: они в активной разработке.
- Не коммитит артефакты сборки (`.pio/`, `managed_components/`, `build/`),
  секреты, локальные пути.
- Не создаёт релизы и теги без задачи.

## Хранилище и права

- Организация: `pusi-os`. Аккаунт-владелец: `teletonn`.
- Новые репозитории лягут рядом: приложение Pusi и остальное —
  позже; пока из кода заливаем только этот репозиторий.
- Все новые проекты называются брендами Pusi-os; чужие имена в новых
  файлах не используем.

## Как проверить себя перед пушем

```sh
git diff --cached        # диф занесённого — глазами
grep -rn "TODO-AGENT" .  # свои метки убраны
make -C test             # если менял код: тесты на хосте
```

Документацию и прошивку проверяют по-разному: для текстов достаточно
глаз и ссылок; для кода — `make -C test` и сборка затронутого `[env:]`.
